WMS - Windows - diagnoza problemu z logowaniem (krok po kroku)
==============================================================

Cel:
- Projekt "odpala się", ale logowanie nie działa.
- Poniższe kroki mają to naprawić bez zgadywania.

Wymagania:
- Windows + PowerShell
- Docker Desktop uruchomiony
- Projekt sklonowany lokalnie

Po git clone NIE MA plikow .env w repozytorium (sekrety).
Utworz je lokalnie ze wzorcow:
- backend:  skopiuj backend\.env.example -> backend\.env i uzupelnij JWT_SECRET_KEY, ADMIN_PASSWORD
- frontend: skopiuj frontend\.env.example -> frontend\.env (opcjonalnie .env.local dla nadpisania)

==============================================================
PULAPKA NR 0 (backend resetuje sie w kolko, blad "input_value=...")
==============================================================
Backend ma walidator, ktory ODRZUCA dwa konkretne stringi:
- ADMIN_PASSWORD=Admin123!     -> blad ValidationError, kontener pada
- ADMIN_PASSWORD=              (puste) -> jw.

Objaw w logach (docker compose logs backend):
   ValidationError ... ADMIN_PASSWORD ... input_value='Admin123!'
   "ADMIN_PASSWORD zawiera domyslna wartosc."

Backend pada -> restart on-failure -> wstaje znowu -> pada -> loop.
Wyglada to jak "problem z haslem w dockerze", ale to walidacja
w aplikacji, nie w MySQL.

ROZWIAZANIE:
0) NAJPIERW — Windows: zmienna srodowiskowa NADPISUJE plik .env.
   Jesli w systemie jest ADMIN_PASSWORD=Admin123!, Pydantic zawsze
   dostanie Admin123! mimo mocnego hasla w .env.
   W PowerShell (nowe okno):
       [Environment]::GetEnvironmentVariable("ADMIN_PASSWORD", "User")
       [Environment]::GetEnvironmentVariable("ADMIN_PASSWORD", "Machine")
   Jak cos wyskoczy z "Admin123!" — usun (tymczasowo w tej sesji):
       Remove-Item Env:ADMIN_PASSWORD
   Albo trwale: Ustawienia Windows -> Zmienne srodowiskowe -> User
   -> jesli jest ADMIN_PASSWORD, usun. Zrestartuj terminal / VS Code.

1) Otworz backend\.env i zmien ADMIN_PASSWORD na cokolwiek INNEGO
   niz dokladnie "Admin123!", np.:
       ADMIN_PASSWORD=DevWmsAdmin2026
2) Zapisz plik.
3) Sprawdz, ze Python czyta TEN plik (w katalogu backend):
       cd backend
       Get-Content .env | Select-String ADMIN
   (Jesli blad "Cannot find path" — plik sie nazywa .env.txt albo jest
   w zlym folderze.)
4) W backend wykonaj:
       docker compose down -v
       docker compose up --build
   (lub uruchom uvicorn Z KATALOGU backend: python -m uvicorn ...)
5) Loguj sie: 00001 / <to co wpisales w ADMIN_PASSWORD> (albo wg bazy)

UWAGA: ADMIN_PASSWORD jest uzywane tylko przy SEEDZIE czystej bazy
(pierwsze uruchomienie po "down -v"). Jak baza juz istnieje z innym
admin -> ADMIN_PASSWORD nie ma znaczenia, haslo admina nie zmieni
sie z poziomu .env. Tylko "down -v" + nowy start tworzy admina od
nowa z aktualnym ADMIN_PASSWORD.

==============================================================
PULAPKA NR 1 (90% przypadkow blad "password" / "Access denied")
==============================================================
MySQL w Dockerze przy PIERWSZYM starcie zapisuje haslo do wolumenu.
Pozniejsze zmiany MYSQL_ROOT_PASSWORD w .env / docker-compose.yml
NIE dzialaja - wolumen trzyma stare haslo.

Objaw 1: w logach kontenera "Access denied for user 'root'@..."
Objaw 2: "MYSQL_ROOT_PASSWORD specified, but data directory is
         initialized with another password"
Objaw 3: backend ciagle restartuje, baza nie chce wstac

ROZWIAZANIE (kasuje dane bazy, zaczyna od zera):
   cd backend
   docker compose down -v       <- KLUCZOWE -v
   docker compose up --build

Po tym admin zostanie zaseedowany od nowa:
   Login:  00001
   Haslo:  Admin1234

==============================================================
PULAPKA NR 2 (konto zablokowane po 5 zlych probach)
==============================================================
Po 5 nieudanych logowaniach konto jest blokowane na 5 minut.
Sprawdzenie:
   docker compose exec db mysql -uroot -ppassword -e "USE wms_db; SELECT login_code,is_active,failed_login_attempts,locked_until FROM users WHERE email='admin@wms.pl';"

Odblokowanie reczne (bez utraty danych):
   docker compose exec db mysql -uroot -ppassword -e "USE wms_db; UPDATE users SET failed_login_attempts=0, locked_until=NULL WHERE email='admin@wms.pl';"


Domyslne dane administratora (z istniejacej zaseedowanej bazy):
- LOGIN: 00001
- HASLO: Admin1234

Uwaga: ADMIN_PASSWORD w backend\.env (DevWmsAdmin2026) jest uzywane TYLKO przy
pierwszym seedzie na czystej bazie. Jesli baza juz istnieje (kolega dostal
backup albo poprzedni seed) — haslo to nadal Admin1234.

Uwaga bezpieczenstwa: to sa sekrety developerskie w repo — na produkcji wygeneruj wlasne.

--------------------------------------------------------------
KROK 1: Uruchom backend i bazę (Docker)
--------------------------------------------------------------
WYMAGANIA:
- Docker Desktop URUCHOMIONY (zielona ikona w trayu)
- Tryb: Linux containers (nie Windows containers)
- Settings -> Resources: min. 4 GB RAM, 2 CPU

OPCJA A — automatyczny start (zalecane):
1) Otwórz PowerShell.
2) Wejdź do katalogu backend:
   cd "<SCIEZKA_DO_PROJEKTU>\backend"
3) Uruchom skrypt:
   powershell -ExecutionPolicy Bypass -File .\start-windows.ps1

Skrypt zatrzyma stare kontenery, zbuduje od nowa, poczeka az backend
bedzie zdrowy i pokaze adresy do logowania.

OPCJA B — recznie:
1) cd "<SCIEZKA_DO_PROJEKTU>\backend"
2) docker compose down -v
3) docker compose up --build

Uwagi:
- Backend dziala na: http://localhost:8000
- MySQL na hoscie: port 3307 (zeby nie kolidowal z lokalnym MySQL na Windows)
- Wewnatrz dockera baza jest pod hostem "db" port 3306 (tak jak w .env)

--------------------------------------------------------------
KROK 2: Uruchom frontend
--------------------------------------------------------------
1) Otwórz DRUGI terminal PowerShell.
2) Wejdź do katalogu frontend:
   cd "<SCIEZKA_DO_PROJEKTU>\frontend"
3) Uruchom:
   npm install
   npm run dev

Frontend domyślnie działa na:
- http://localhost:5173

--------------------------------------------------------------
KROK 3: Sprawdź konfigurację frontendu (bardzo ważne)
--------------------------------------------------------------
Plik:
- <SCIEZKA_DO_PROJEKTU>\frontend\.env.local

Musi zawierać:
VITE_API_URL=http://localhost:8000/api/v1

Jeśli zmienisz ten plik:
- zatrzymaj frontend (Ctrl + C)
- uruchom ponownie: npm run dev

--------------------------------------------------------------
KROK 4: Sprawdź czy backend widzi bazę
--------------------------------------------------------------
W PowerShell wpisz:
Invoke-RestMethod http://localhost:8000/api/health

Oczekiwany wynik:
- status = ok
- database = ok

Jeśli database != ok:
- problem jest po stronie połączenia z MySQL.

--------------------------------------------------------------
KROK 5: Sprawdź konto admina w bazie
--------------------------------------------------------------
Wariant A — z dockera (jeden kontener db):
   cd backend
   docker compose exec db mysql -uroot -ppassword -e "USE wms_db; SELECT id,login_code,email,role,is_active,failed_login_attempts,locked_until FROM users WHERE email='admin@wms.pl';"

Wariant B — z Windowsa przez port 3307 (jesli masz mysql client):
   mysql -uroot -ppassword -h 127.0.0.1 -P 3307 -e "USE wms_db; SELECT id,login_code,email,role,is_active FROM users WHERE email='admin@wms.pl';"

Ważne:
- logowanie odbywa się po login_code (np. 00001), NIE po emailu.

--------------------------------------------------------------
KROK 6: Najczęstsza przyczyna
--------------------------------------------------------------
Jeśli wpisujesz:
- login: admin@wms.pl
to będzie błąd.

Poprawnie:
- login: login_code z tabeli users
- hasło: hasło admina

--------------------------------------------------------------
KROK 7: Reset admina (jeśli dalej nie działa)
--------------------------------------------------------------
1) W pliku backend\.env ustaw:
   ADMIN_EMAIL=admin@wms.pl
   ADMIN_PASSWORD=<NOWE_HASLO_ADMINA>

2) Usuń istniejącego admina z bazy:
   docker compose exec db mysql -uroot -ppassword -e "USE wms_db; DELETE FROM users WHERE email='admin@wms.pl';"

3) Zrestartuj backend:
   docker compose restart backend

4) Sprawdź, jaki login_code dostał nowy admin:
   docker compose exec db mysql -uroot -ppassword -e "USE wms_db; SELECT login_code,email,role,is_active FROM users WHERE email='admin@wms.pl';"

5) Zaloguj się:
- login: login_code z punktu 4
- hasło: to ustawione w ADMIN_PASSWORD

--------------------------------------------------------------
TYPOWE PROBLEMY ZE STARTEM DOCKERA (Windows)
--------------------------------------------------------------
1) "error during connect: ... //./pipe/docker_engine"
   - Docker Desktop nie wystartowal. Otworz aplikacje, poczekaj.

2) "bind: address already in use" na porcie 3306 lub 3307
   - Zatrzymaj lokalny MySQL: 
     Stop-Service MySQL80
   - Albo zmien port w docker-compose.yml (np. 3308:3306).

3) Kontener db ciagle restartuje
   - Reset wolumenu (skasuje dane bazy):
     docker compose down -v
     docker compose up --build

4) "no matching manifest for windows/amd64"
   - Docker jest w trybie Windows containers.
   - Right-click na ikone Docker -> "Switch to Linux containers".

5) Backend dalej restartuje (ValueError przy starcie)
   - Sprawdz czy backend\.env ma:
     * JWT_SECRET_KEY (min. 32 znaki)
     * ADMIN_PASSWORD (nie puste)
   - Po zmianach: docker compose up --build

KOMENDY DIAGNOSTYCZNE:
   docker compose ps
   docker compose logs db --tail=80
   docker compose logs backend --tail=80
